17. RBAC — what each role can do

Full = all actions incl. configuration · Approve = decide and move money · Edit = create and update · View = read-only · — = no access (menu hidden, API 403). Roles map to Spring Authorization Server scopes; per-object checks (this seller’s orders, this practitioner’s calendar) run in OpenFGA. Privileged actions are step-up authenticated, reason-coded and audited; approvals over medium risk need two different people.

22. Cloud choice — AWS, Google Cloud or Azure — and what it costs

The cloud is not decided yet, so the platform is built cloud-neutral: everything runs on Kubernetes, infrastructure is Terraform with one module set per cloud behind the same interface, and CI/CD targets AWS, Google Cloud and Azure from the same pipeline. Pick one primary later (and optionally a second for DR); running two actively doubles fixed costs. Cloudflare sits in front of every option, so DNS, CDN, WAF and the web front-ends do not move when the backend cloud does. Ranges are launch-scale planning estimates (≈50k monthly shoppers, 600 sellers) to validate with each provider’s calculator and committed-use quotes.
